# PSX — Password Manager

PSX is a simple password manager for Android, written in Dart with Flutter.
After signing in with Firebase email authentication, you can store, view, edit
and delete account credentials (account name, login, password). Everything is
saved on the device in a SQLCipher-encrypted SQLite database.

The app targets Android. Flutter's iOS, web and desktop folders are present from
the project template, but only Android is built and tested.

## Features

- Email/password sign-in, registration and password reset (Firebase Auth +
  `firebase_ui_auth`)
- Add accounts, with a confirm-password field and show/hide toggles
- List saved accounts as cards with edit and delete buttons
- On-device storage in an encrypted database (`sqflite_sqlcipher`)
- Database name and encryption key read from a `.env` file, not hard-coded

## Project structure

```
lib/
├── main.dart                    # Entry point: starts Firebase, loads .env, runs the app
├── firebase_options.dart        # Generated by FlutterFire CLI (gitignored)
├── models/
│   └── psxUserInfo.dart         # Account record + map conversion
├── services/
│   ├── database_service.dart    # Encrypted DB: create, insert, query, update, delete
│   └── data_service.dart        # In-memory list (left over from Version 1)
└── widgets/
    ├── auth_gate.dart           # Shows sign-in, or the app once signed in
    ├── landing.dart             # Main shell with the side navigation rail
    ├── homescreen.dart          # Home: profile and sign-out
    ├── accountList.dart         # Saved accounts list with edit/delete
    └── accountManagement.dart   # Add/edit account form
assets/                          # Images (vault logo etc.)
android/                         # Gradle/Android build configuration
```

### How it works

1. `main.dart` starts Firebase, loads `.env` and shows `AuthGate`.
2. `AuthGate` listens to `FirebaseAuth.authStateChanges()`. Signed-out users see
   the FirebaseUI sign-in screen. Signed-in users see `LandingPage`.
3. `LandingPage` creates the encrypted database and offers three pages through
   a `NavigationRail`: **Home**, **Account list** and **Add account**.
4. All storage goes through `DataBase` in `database_service.dart`. It opens the
   database with the `.env` password for each operation. The table name is
   the same as the database name.

## Getting started

### Prerequisites

- Flutter SDK (stable channel) with Android tooling (`flutter doctor` should be
  clean)
- Android Studio or the Android SDK, with an emulator or device
- Access to a Firebase project with **Email/Password** sign-in enabled

### 1. Clone and fetch packages

```bash
git clone https://github.com/JaDaar/android-psx.git
cd android-psx
flutter pub get
```

### 2. Create `.env`

Create a `.env` file in the project root. It is gitignored and bundled into the
app as an asset.

```env
DB_PASSWORD=choose-a-strong-database-key
DBName=psx_accounts
```

> Changing `DB_PASSWORD` after a database exists makes that database
> unreadable. Uninstall the app, or clear its data, to start fresh.

### 3. Configure Firebase

`lib/firebase_options.dart` is gitignored, so generate it for your Firebase
project:

```bash
dart pub global activate flutterfire_cli
flutterfire configure
```

This also writes `android/app/google-services.json`.

### 4. Run

```bash
flutter devices            # find your emulator/device id
flutter run -d emulator-5554
```

Build an APK with `flutter build apk --debug` (or `--release`; release builds
are signed with the debug key for now).

## Troubleshooting

- **"Could not close incremental caches" (Kotlin)**: this happens on Windows
  when the project and the pub cache are on different drives.
  `android/gradle.properties` sets `kotlin.incremental=false` to avoid it.
- **`Registrar` / v1 embedding compile errors**: a plugin is too old for
  current Flutter. Run `flutter pub upgrade`.
- **Git "dubious ownership" on a non-NTFS drive**: run
  `git config --global --add safe.directory <path-to-repo>`.

## Security notes

This is a learning project, not a hardened password manager:

- `.env` is packaged inside the APK, so the database key can be pulled out of
  the app. A production app would derive the key from the user's credentials or
  keep it in the Android Keystore (e.g. `flutter_secure_storage`).
- Passwords are shown in plain text on the account list.
- The confirm-password check ignores case.

## Known issues

- The account list can show old data right after an edit or delete. It reloads
  before the database operation finishes.
- `DataBase.updateRecord` overwrites its `password` parameter with the DB key.
  It is currently unused; `updateUserAccount` is used instead.
- The Home and List items on the navigation rail are both labelled "List".
